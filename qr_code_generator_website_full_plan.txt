============================================================
1. PROJECT OVERVIEW
============================================================

Project goal:
Build a modern, responsive website where users can generate, customize, download, and manage QR codes. The website should be simple for first-time visitors while offering advanced features for registered users and paid customers.

Suggested working name:
QR Studio (placeholder name; check domain and trademark availability before using it).

Main value proposition:
Create attractive, scannable QR codes quickly for URLs, text, Wi-Fi, contact cards, business details, and other supported data types.

Target users:
- Individuals and students
- Small businesses and shops
- Restaurants and cafes
- Marketing teams and agencies
- Event organizers
- Freelancers and web developers
- Businesses that need trackable QR campaigns

Business model:
- Free static QR code generation
- Optional accounts for saving designs and history
- Paid plans for dynamic QR codes, analytics, branding, bulk generation, and team features
- Optional business/agency plan

Important distinction:
A static QR code stores its destination or content directly in the code. Its encoded content cannot be changed after printing. A dynamic QR code points to a redirect URL controlled by the website, allowing the destination to be changed and scan analytics to be collected. Dynamic codes require reliable redirect infrastructure and should be presented clearly as a separate feature.

3. QR CODE TYPES
============================================================

Prioritize these types for the first release:

A. URL / Website
- Input: full URL
- Validate and normalize the URL
- Optionally allow users to test the destination
- Warn users about unsafe or suspicious URLs where possible

B. Plain Text
- Input: text or message
- Support line breaks and Unicode
- Show character count and QR complexity feedback

C. Wi-Fi
- Inputs: network name (SSID), security type, password, hidden network
- Support common security types, including WPA/WPA2 and open networks
- Explain that anyone scanning the code may gain access to the network if credentials are embedded

D. vCard / Contact
- Name, organization, job title, phone, email, website, address
- Generate a standard vCard-compatible QR payload
- Test compatibility with common phone contact apps

E. Email
- Email address, subject, optional message
- Generate a mailto payload

F. Phone
- Phone number
- Generate a tel payload

G. SMS
- Phone number and optional prefilled message
- Generate a supported SMS payload and test on major mobile platforms

H. WhatsApp
- Phone number in international format
- Optional prefilled message
- Generate a link using the official WhatsApp click-to-chat URL format

I. Location / Map
- Latitude and longitude or a map URL
- Prefer a validated map link for consistent cross-device behavior

J. Event / Calendar
- Event name, start/end date and time, location, description
- Use a supported calendar payload format and test with major calendar apps

K. Social Media
- Profile or page URL for supported platforms
- Validate URL format

Later types:
- App download links
- Payment links (country/provider-specific; clearly test and document limitations)
- Product details
- Multi-link landing page
- Menu or catalog links
- Business review links
- Custom URL redirects
- Bulk-generated QR codes

Note:
QR payload limits depend on content and error-correction level. Large payloads produce denser codes and may be harder to scan. Show a helpful warning rather than promising every input will work.

6. STATIC AND DYNAMIC QR CODE DESIGN
============================================================

Static QR codes:
- Generate the QR image from the supplied payload
- Can be generated in the browser or on the server
- Do not require redirect hosting
- Do not need scan tracking
- Their encoded destination cannot be edited after download/printing
- Avoid storing user-provided content unless the user explicitly saves it

Dynamic QR codes:
- QR code contains a website-controlled short URL, for example:
  https://example.com/r/AbC123
- The redirect service resolves the code to its current destination
- Owner can update the destination without reprinting the code
- Scan events can be recorded for analytics
- Requires authentication and ownership checks for management
- Requires rate limits, abuse prevention, monitoring, and reliable uptime
- Destination changes should be logged for security and accountability

Dynamic QR redirect requirements:
- Validate destination URLs
- Block dangerous schemes such as javascript: and data:
- Apply abuse detection and reporting
- Avoid open-redirect abuse by restricting redirect behavior to managed QR records
- Protect redirect endpoints from excessive traffic
- Consider bot filtering and privacy-friendly analytics
- Make clear that scan counts may include bots or repeated scans
- Do not collect unnecessary personal data or precise location without a lawful basis and clear notice

Recommended launch approach:
Start with static QR codes. Add dynamic QR codes only after the basic generator is stable and there is a plan for hosting, abuse prevention, privacy, and analytics.

10. SUGGESTED LARAVEL STRUCTURE
============================================================

Possible classes:
- QrCodeController: accepts requests and returns preview/download responses
- QrCodeService: creates QR images
- QrPayloadBuilder: converts form values into type-specific payloads
- QrCodeRepository or Eloquent models: persists saved QR codes
- DynamicQrRedirectController: resolves public dynamic codes
- QrAnalyticsService: records and aggregates scan events
- SubscriptionService: checks feature limits
- ExportService: prepares files and ZIP exports
- Controllers/Form Requests: validation boundaries
- Policies: authorization and ownership rules

Possible routes:
- GET /qr-generator
- POST /qr/preview
- POST /qr/download
- GET /qr-codes (authenticated dashboard)
- POST /qr-codes (save)
- GET /qr-codes/{qrCode}
- PATCH /qr-codes/{qrCode}
- DELETE /qr-codes/{qrCode}
- GET /r/{publicCode} (dynamic redirect)
- GET /qr-codes/{qrCode}/analytics (authenticated and authorized)

Use named routes, Form Request validation, policies, CSRF protection for web forms, and rate limits. Never rely only on hiding UI controls to enforce permissions.

11. SECURITY, PRIVACY, AND RELIABILITY
============================================================

Security checklist:
- Validate and normalize every QR input
- Escape user content when rendering HTML
- Validate uploaded logo MIME type, extension, size, and actual file content
- Re-encode or sanitize image uploads where practical
- Store uploads outside executable/public paths when possible
- Use authorization policies for saved QR records
- Rate-limit generation, login, redirects, and expensive exports
- Protect authentication and password reset flows
- Verify payment webhooks using provider signatures
- Use idempotency for webhook processing
- Avoid logging passwords, tokens, Wi-Fi passwords, or sensitive QR payloads
- Keep dependencies patched
- Use HTTPS in production
- Back up the database and test restoration
- Monitor errors, latency, storage use, and unusual redirect traffic

Privacy checklist:
- Publish a clear privacy policy
- Explain what data is collected and why
- Let users generate static QR codes without saving content when feasible
- Provide account/data deletion for registered users
- Set a retention period for scan analytics
- Minimize IP address retention; if IPs are used for abuse prevention, document the purpose and retention
- Make optional analytics and tracking transparent
- Review applicable privacy and consumer laws for the countries served

Abuse prevention:
- Block malicious redirect destinations
- Provide a way to report abusive QR destinations
- Monitor phishing and spam patterns
- Prevent dynamic QR codes from becoming an unrestricted redirect service
- Add account and plan limits
- Provide an abuse response and suspension process

============================================================
19. FINAL RECOMMENDATION
============================================================

Build a polished static QR generator first. Focus on speed, simple forms, accurate QR payloads, reliable PNG/SVG downloads, safe customization, mobile usability, and search-friendly tool pages.

Do not begin with subscriptions, team management, bulk exports, API access, and advanced analytics all at once. These features add complexity and should follow evidence that users need them.

Recommended first milestone:
A visitor can open the website, select URL/Text/Wi-Fi/vCard, enter information, preview the QR code, customize its colors, download PNG or SVG, and scan it successfully on a phone without creating an account.

Once that milestone is reliable, add saved codes, then dynamic QR codes and analytics, and finally monetization and business features.
